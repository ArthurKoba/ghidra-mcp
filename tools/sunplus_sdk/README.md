# Sunplus DSP SDK — экспериментальная сборка

Профиль `adsp218x-d16-candidate`: 24-битное слово PM, 16-битное слово DM,
порядок байтов внутри слова — big-endian. Адреса CLI, ELF и символов задаются
**в словах соответствующего пространства**, а размеры файлов — в байтах.
Это инструменты сборки и адаптер Ghidra, не готовая прошивка SPHE8202R.

## Состав и готовность

В комплект входят Linux x86-64 `as218x`, `ld21`, Python CLI/API, исходники
инструментов с лицензией GPL-2.0-or-later и локальным патчем, синтетический
пример, кандидат языка Ghidra и загрузчик SDK ELF для Ghidra 12.1.3.

Сборка `.dsp → .o → image.elf → pm.bin/dm.bin` проверяется отдельно от
корректности исполнения DSP. Процессорная модель **не прошла полную приёмку**
на пяти образах AudioRush. C-компилятор G21 не включён: его сборка, ABI,
библиотека исполнения и корректность кода для Sunplus не приняты.

## Использование

Требуются Python 3.10+, Linux x86-64, совместимая glibc, libelf.so.1 и libz.so.1. Нативные инструменты
этой поставки собраны на Debian 12. Другие платформы требуют отдельной сборки.

```bash
/path/to/sdk/bin/sunplus-dsp doctor
/path/to/sdk/bin/sunplus-dsp build /path/to/sdk/examples/core.dsp \
  --output ./new-build --pm-base 0x1800 --dm-base 0x100 --entry-word 0x1800
/path/to/sdk/bin/sunplus-dsp inspect ./new-build/image.elf
```

Каталог результата должен отсутствовать. При ошибке сохраняется `build.log`,
но успешный `image.json` не создаётся. Неопределённые символы, неподдержанные
секции, остаточные релокации, выход за диапазон и неполные слова отклоняются.

`program0` и `pmdata0` связываются в `int_pm`; `data0` — в `int_dm`.
Несколько файлов `.dsp` передаются одной команде build. `image.map` содержит
полную карту линковщика. CLI переносит разрешённые символы из этой карты
в `.symtab` результирующего ELF, не изменяя PM/DM. PM-метка не объявляется
функцией только по имени. `--entry-word` явно задаёт `e_entry` нового ELF;
без опции сохраняется нулевой заголовок исходного `ld21`.

## Загрузка в Ghidra

Архив `ghidra/SunplusDspSDK-ghidra_12.1.3.zip` содержит язык
`SunplusSPHEAudioDSP:BE:16:default` и загрузчик `Sunplus DSP SDK ELF (PM24/DM16)`.
Это кандидат для отдельной тестовой установки Ghidra 12.1.3, не автоматический
апдейт рабочего Analyzer. **Не устанавливать две копии одного LanguageID**:
если Sunplus уже входит в установленный GhidraMCP, проверять обновление в
отдельной установке или использовать общий кандидат MCP вместо standalone.

Загрузчик различает PM и DM, переводит адреса слов в байтовые адреса Java API,
переносит метки и явную точку входа. Обе области SDK LDF объявлены RAM:
загрузчик не делает PM ошибочно read-only. Он не переписывает старые проекты,
не считает каждый символ функцией и не выдаёт пользовательский ELF за MIPS.

Установка языка сама по себе не доказывает обновление сохранённых инструкций,
границ функций, C или контекстов аппаратных циклов. Перед миграцией AudioRush
нужны сохранённая контрольная точка, проверка модели через Analyzer MCP,
полное C-покрытие, сохранение и независимое чтение. Исходные файлы прошивки
нельзя подменять результатом сборки этого примера.

## Точные формы констант

SDK добавляет явные псевдооперации в синтаксис ассемблера:

```text
if ne ar = inc_const(2);   /* именно INC константы 2, а не DEC константы 4 */
ar = dec_const(4);
ar = -ax0 + 0x100;         /* штатное написание constant - X в Open21xx */
```

Это не новые машинные инструкции. Они используют штатную проверку допустимых
констант и сохраняют выбранную операцию при кодировании. Нельзя заменять
побитную проверку вставками `.word/.byte` с исходным словом.

## Повторная сборка и ограничения

`source/open21xx/` содержит полный соответствующий исходный код; патч находится
в `patches/`. Для сборки нужны C-компилятор, make, bison, flex и заголовки/libelf.
`rebuild-tools.sh` собирает инструменты в новом каталоге и не изменяет SDK.

Не приняты: полная модель аппаратных стеков и вложенных вызовов, все режимы
MAC/округления/насыщения, адресная генерация BIT_REV и циклических буферов,
связь внутренних пространств DSP с трёхбайтовыми CPU-окнами SPHE, точный
целевой ABI C и аппаратное исполнение. Нулевые предупреждения C не заменяют
этих доказательств. Данные/неразмеченные участки исходных модулей не считаются
проверенными инструкциями.

Открытые исходники: `wodz/open21xx` revision
`55259d045abf100b83a040c3d2811613855ee96b`.
Закрытые кодеки и фирменные исполняемые утилиты SDK SPHE8202L в поставку
**не включены**. Лицензии каждого компонента находятся в `LICENSES/`.

## SPHE8202L: донорский интерфейс CPU↔DSP (исследовательский адаптер)

Модуль `donor_sphe8202l.py` реализует **отдельный** интерфейс сравнения с
форком `ArthurKoba/SPHE8202L`, ревизия
`78143e63d9b66b0ba1c5c83dd1cc13c2f173a010`. В исходный DSP SDK
не включены закрытые коды, упакованные ROM-образы и оригинальные заголовки.

Он предоставляет дескриптор `DonorCodecDescriptor` (`<IHHH`, 10 байт),
упаковку/распаковку трёхбайтовых CPU-visible PCM-слов, адресацию страниц
SDRAM в uncached-псевдониме и порядок записи параметра/команды
`AudioIOControl`. Физическая семантика SPHE8202R **не выводится** из этих
интерфейсов автоматически.

**Критическое различие карт:** `h/memmap_dsp3.h` у донора выбирает
`memmap_dsp3_8202D.h` для `IC_8202L`, а не `memmap_dsp3_82XX.h`.
`read_donor_memory_profiles(fork, "IC_8202L")` различает их, не смешивая
размеры `IM/DM/PM` с внутренними пространствами Sunplus DSP в Ghidra.
В донорском AC-3 обнаружено расхождение комментария и макроса PM (9 против
38.7K) — по комментарию нельзя определять размер для загрузчика.
Оригинальный `DSP3_SRC` и DSP-компилятор в форке отсутствуют, его GCC
предназначен для MIPS. Для DSP используется независимый `as218x/ld21`.

Пример проверки различий без копирования содержимого исходников:

```python
from tools.sunplus_sdk.donor_sphe8202l import read_donor_memory_profiles
active = read_donor_memory_profiles('/path/to/SPHE8202L', 'IC_8202L')
legacy = read_donor_memory_profiles('/path/to/SPHE8202L', 'IC_8200')
print(active['AC3'], legacy['AC3'])
```

Сведения из донора — **внешнее сравнение, а не доказательство поведения
SPHE8202R**. Для такого доказательства нужны нативный код, сгенерированный
Analyzer C, прослеживание через Java и сохранённый/повторно прочитанный
канонический Analysis.

## Подготовка контейнера родственных DSP-образов и проверка provenance

Для сторонних DSP-образов из `SPHE8202L` имеется отдельный исследовательский
контейнер: **raw DEFLATE + CRC32/ISIZE** без gzip-заголовка. Все 52 исходных
образа проходят проверку CRC32, точного размера и полной распаковки; среди них
41 уникальный по SHA-256. У 47 образов обнаружено **два завершающих нулевых
байта**, у пяти такого дополнения нет. Это наблюдение, а не архитектурная
инструкция и не правило загрузчика SPHE8202R.

Команды ниже предназначены для *собственного* PM24-кода:

```bash
python -m tools.sunplus_sdk donor-pack own-pm.bin \
  --output own-pm.bin.gz --legacy-two-byte-tail
python -m tools.sunplus_sdk donor-unpack own-pm.bin.gz \
  --output restored-pm.bin --strip-two-byte-tail
cmp own-pm.bin restored-pm.bin
```

Воссозданные байты после распаковки проверяются побитно; сжатые байты не обязаны
совпадать с `fgzip2.exe` 2000-х годов. Исполнение на устройстве, загрузочный
формат SPHE8202R и полнота алгоритмов остаются **UNKNOWN**. Утилита не выполняет
прошивку и не поставляет оригинальные proprietary DSP ROM.

`donor-match` сравнивает уже сохранённые нативные инструкции Ghidra со всеми
распакованными родственными PM-образами:

```bash
python -m tools.sunplus_sdk donor-match \
  --fork /path/to/SPHE8202L \
  --corpus /path/to/native-instruction-corpus \
  --output /tmp/dsp-donor-evidence.json --min-run 12
```

Сопоставления выполняются только по **подряд идущим 24-битным машинным словам
с проверенным владельцем функции**. Данные, недекодированные области и
безымянные переходы не используются как доказательство. Итоговый JSON содержит
метаданные, SHA-256, диапазоны и статусы, но не оригинальные ROM-байты.
Сходство кодировок не доказывает идентичность CPU/DSP ABI или поведения;
все семантические связи требуют Java-проверки и сохранения в каноническом
проекте Analyzer на этапе системной интеграции.
